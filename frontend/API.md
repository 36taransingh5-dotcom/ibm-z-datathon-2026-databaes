# Payment risk API — contract v1 (proposal)

**Status:** proposed by frontend, not yet confirmed by backend.
The frontend in this folder is built against exactly this shape. If the backend
differs, change it here first and the frontend will be updated to match.

- Base URL (LinuxONE VM): `http://148.100.98.249:8000`
- Base URL (local dev): `http://localhost:8000`
- All request and response bodies are JSON (`Content-Type: application/json`).
- All timestamps are UTC ISO-8601 with a `Z` suffix.
- Money is a JSON number of major units (e.g. `1250.50` = £1250.50), plus a
  separate ISO-4217 `currency` string. The frontend never sends a formatted string.

---

## POST /score

Score a payment the user is about to make. Called on form submit, before any
money is considered sent.

### Request

```json
{
  "client_txn_id": "c_9f2a7b41-3d11-4c0e-a6f5-2b8e4d7c1a90",
  "amount": 1250.50,
  "currency": "GBP",
  "payee": "Acme Supplies Ltd",
  "new_payee": true
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `client_txn_id` | string | yes | Generated by the frontend. Use it for idempotency and for correlating logs. |
| `amount` | number | yes | `> 0`, at most 2 decimal places. |
| `currency` | string | yes | ISO-4217. The demo sends `GBP`. |
| `payee` | string | yes | 1–140 chars, as typed by the user. |
| `new_payee` | boolean | yes | `true` if the user flagged this as a payee they have not paid before. |

### Response `200`

```json
{
  "txn_id": "txn_01HQ8ZK3M4N5P6R7S8T9V0W1X2",
  "decision": "review",
  "risk_score": 0.82,
  "reasons": [
    {
      "code": "NEW_PAYEE_HIGH_VALUE",
      "message": "First payment to this payee, and it is above your usual amount.",
      "severity": "high"
    },
    {
      "code": "AMOUNT_OUTLIER",
      "message": "This is 6x your median payment over the last 90 days.",
      "severity": "medium"
    }
  ],
  "scored_at": "2026-10-18T09:12:03Z"
}
```

| Field | Type | Notes |
|---|---|---|
| `txn_id` | string | Server-assigned. The frontend sends this back to `/score/confirm`. |
| `decision` | enum | `"allow"` or `"review"`. **Authoritative** — the frontend branches on this, not on `risk_score`. |
| `risk_score` | number | `0.0`–`1.0`, advisory, displayed only. |
| `reasons` | array | May be empty for `allow`. **Required and non-empty for `review`** — the pause screen lists these verbatim. |
| `reasons[].code` | string | Stable `SCREAMING_SNAKE_CASE` identifier. |
| `reasons[].message` | string | Human-readable, shown directly to the user. Write it as a full sentence. |
| `reasons[].severity` | enum | `"low"`, `"medium"` or `"high"`. Drives the colour of the chip. |
| `scored_at` | string | ISO-8601 UTC. |

**Frontend behaviour:**
- `decision: "allow"` → "Sent" confirmation screen.
- `decision: "review"` → pause screen listing every `reasons[].message`, with **Confirm** and **Cancel**.

## POST /score/confirm

Record what the user chose on the pause screen. Only called after a
`decision: "review"` response.

### Request

```json
{
  "txn_id": "txn_01HQ8ZK3M4N5P6R7S8T9V0W1X2",
  "action": "confirm"
}
```

`action` is `"confirm"` (user chose to send anyway) or `"cancel"` (user backed out).

### Response `200`

```json
{
  "txn_id": "txn_01HQ8ZK3M4N5P6R7S8T9V0W1X2",
  "status": "sent",
  "recorded_at": "2026-10-18T09:12:41Z"
}
```

`status` is `"sent"` or `"cancelled"`, mirroring the action taken.

## GET /audit

The audit log view. Newest entry first.

### Response `200`

```json
{
  "entries": [
    {
      "txn_id": "txn_01HQ8ZK3M4N5P6R7S8T9V0W1X2",
      "timestamp": "2026-10-18T09:12:03Z",
      "amount": 1250.50,
      "currency": "GBP",
      "payee": "Acme Supplies Ltd",
      "new_payee": true,
      "decision": "review",
      "risk_score": 0.82,
      "reasons": [
        {
          "code": "NEW_PAYEE_HIGH_VALUE",
          "message": "First payment to this payee, and it is above your usual amount.",
          "severity": "high"
        }
      ],
      "outcome": "sent"
    }
  ]
}
```

Each entry is a scored payment plus how it ended:

| Field | Type | Notes |
|---|---|---|
| `outcome` | enum | `"sent"`, `"cancelled"`, or `"pending"` if the user never resolved the pause screen. |

Everything else carries the same meaning as in `/score`.

Optional query params the frontend may start sending later — safe to ignore for now:
`?limit=50`.

## Errors

Any non-`2xx` uses one envelope:

```json
{
  "error": {
    "code": "INVALID_AMOUNT",
    "message": "amount must be greater than 0"
  }
}
```

The frontend shows `error.message` when present and falls back to the HTTP
status otherwise. Status codes used: `400` (validation), `404` (unknown
`txn_id`), `500` (scoring failure).

## Backend checklist

Two things are needed before the frontend can talk to the VM:

1. **CORS.** The page runs from a different origin (a local file or
   `http://localhost:*`), so the API must send CORS headers or every request
   fails in the browser before it reaches you. For FastAPI:

   ```python
   from fastapi.middleware.cors import CORSMiddleware

   app.add_middleware(
       CORSMiddleware,
       allow_origins=["*"],          # fine for the demo; tighten if it goes further
       allow_methods=["GET", "POST", "OPTIONS"],
       allow_headers=["Content-Type"],
   )
   ```

   The `OPTIONS` preflight must succeed too — a `POST` with a JSON content type
   always triggers one.

2. **Port 8000 reachable on the VM:**

   ```
   sudo iptables -I INPUT -p tcp --dport 8000 -j ACCEPT
   ```

   Note this opens 8000 to any source, and the rule is not persistent across a
   reboot. Fine for the datathon; worth narrowing to our own IPs if the VM
   stays up afterwards.

   Also bind the server to all interfaces, not just loopback, or the port will
   be open but nothing will answer on it:
   `uvicorn main:app --host 0.0.0.0 --port 8000`

One more thing to be aware of: if the frontend is ever served over **https**,
browsers will block plain-`http` calls to the VM as mixed content. Serve the
page over http (or open the file directly) for the demo.
